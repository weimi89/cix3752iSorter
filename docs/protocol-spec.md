# 分揀機裝置協定規格（由現場日誌逆推）

> 依據：`main_proj/data/cmd.log`（2026-08-31 ~ 09-10，714,571 行、40,870 件包裹）、`main_proj/logic/*.go`（舊版原始碼）、`main_proj/data/conf.json`。
> 欄位語意標示 **[碼]** 表示原始碼有明確用法；**[推斷]** 表示只從日誌值域推斷，待廠商原始碼或實機確認。

## 1. 裝置與連線

| 裝置 | 位址 | 方向 | 協定 |
|---|---|---|---|
| 皮帶線控制器（belt） | `192.168.177.100:10006` | 本程式為 TCP client | 文字行協定，`\n` 結尾；送出指令以 `;` 結尾（`KM998 3;\n`） |
| 分揀機集群（sorter，index 0） | `192.168.177.198:10006` | 本程式為 TCP client | 同上 |
| 系統燈／蜂鳴器（sysLed） | 與分揀機**共用同一條連線**（`conf.sysLed.addr == sorter.addr`） | — | `KL` 指令 |
| 相機條碼（camera） | 本程式開 `0.0.0.0:8050` 當 TCP server | Node 端連進來 | 每筆 `條碼@`，`@` 為分隔 |

## 4. 分揀機 → 本程式（上行訊號）

分揀機是一列小車（cart，編號 0–25，`conf.sorter.number=8` 台、`irNum=38` 顆光電）。下 `Kn` 後分揀機回 `~c` 告知**分配到哪台小車**，之後該包裹的所有訊號都以小車號識別 **[碼]**。

| 訊號 | 格式 | 意義 | 欄位 |
|---|---|---|---|
| `~c` | `~c<cart> <a> <b> 1` | **指令受理**：小車 `cart` 承接剛才的 `Kn` **[碼]** | `a` 多半等於 cart [推斷]；`b` 300–476 [推斷] 速度或位置 |
| `~j` | `~j<cart> 1` | **收件**：包裹上車 **[碼]**（推送「收件」事件） | |
| `~g` | `~g<cart> <x> <y>` | **離開頭部**：舊程式以 `~j` 或 `~g` 任一到達即釋放頭部、允許下一個 `Kn` **[碼]** | `x` 多為 -1；`y` 1 或負數 [推斷] |
| `~n` | `~n<cart>` | 包裹到達本集群尾部，需傳給下一集群（單集群現場未出現） **[碼]** | |
| `~e` | `~e<cart>` | **掉落完成**：正常分揀完成 → 狀態 3 **[碼]** | |
| `~k` | `~k<cart> <pos> <pos2>` | **堵塞**：`BlockCid = (10+idx)*100000 + pos*100` **[碼]**；Node 端算格口 `M = floor(pos/10)+1` 發卡件警報 | `pos` 2–73 |
| `~u` | `~u<cart> <pos> <z>` | **丟失／取走**：`LostCid` 同上算法 **[碼]** | `z` 常見 `-999` [推斷] 未知位置 |
| `~q` | `~q<slot> <len> <cart>` | [推斷] 交接確認：皮帶槽 `slot`、長度 `len`、落到小車 `cart`（舊程式未處理） | |
| `~f` | `~f<cart> <cart2> <pos> <a> <b>` | [推斷] 小車間互動／偵測，舊程式未處理，665 次 | |
| `~x` | `~x<cart>` | [推斷] 指令取消回應（`Kx` 後）或清除，291 次 ≈ `Kx` 282 次 | |
| `~y` | `~y<cart> <..4 值>` | [推斷] 光電／位置診斷，舊程式未處理 | |
| `~I` | `~I1` | 分揀機入口光電觸發；`conf.sorter.IInitPac=true` 時以此建包裹（現場 false）**[碼]**；正式機二進位有「Init Pac when ~I」 | 3,887 次 |
| `~v` | `~v<m2> <bits>` | 輸入點（同皮帶） | |
| `~[` | `~[<8 組 8 位十六進位>]` | `Kd[` 查詢光電狀態的回覆（IR 檢查頁用） **[碼]** | |

## 5. 本程式 → 分揀機（下行指令）

| 指令 | 格式 | 意義 |
|---|---|---|
| `Kn` | `Kn 101 01 <pos><side> <speed> <trail> 1` | **分揀指令**。由格口 CID 產生：`pos=(cid/1000)%100`、`side=(cid/100)%10`、`trail=cid%100`、`speed=conf.sorter.speed`。多集群且 `number>2` 時 `trail` 為負值 **[碼]**。例：CID `1004324` → `Kn 101 01 43 100 24 1` |

## 7. 相機／條碼流程

1. 相機把一幀內所有條碼送到 Node `:8051`：`code;coord;type;...@`。
2. 挑選規則（`server.js checkcode1`）：順豐 `SF\d{13}` 最優先 → 合法 QRCode（無 `^` 且長度 >9）→ 一維條碼排除黑名單區間、長度 <9 丟棄 → 同時有 16 碼與 9 碼則拼成 `9碼+16碼`（超商） → 否則取第一個 → 都沒有回 `NoRead`。
3. 5 秒內同一條碼不重複觸發（`NoRead` 例外）。
4. 條碼以 `code@` 送給主程式 `:8050`；主程式在 `~P` 後 `-100~2000ms` 窗口內把條碼綁到最近一件未綁定的包裹（實測 226ms）。
5. 同時向中介機 `GET /api/parcel/{code}` 取格口與面單（契約見 `cix3752iLabelPrint/docs/local-http-api.md`）。

### 中介機回應實測延遲（49,349 筆）

中位 357ms、p90 500ms、p99 898ms、max 1202ms。舊 Node 端 1200ms 主動逾時派 `RS`；主程式 `~O` 到達時仍無格口者走預設口（每日 0.3–0.9%）。`NoRead` 約 7%（`TOerr`）。

## 9. 列印（TSPL）

- 面單圖依 `print_profile`（如 `PAPER-01#100*150`）以 203 DPI（8 px/mm）縮放，`fit: contain`，高度 ≥150mm 者上下各留 2mm 白邊。
- 灰階 → 門檻 200 二值化 → 1 bit 點陣（`>65` 為 1）。
- 指令：`512 bytes 0x00` 前導 + `SIZE w mm,h mm` + profile `cmd`（`DIRECTION 1\r\nSPEED 6\r\nDENSITY 11`）+ `CLS` + `BITMAP x,y,widthBytes,height,0,<data>` + `PRINT 1,1`。
- 印表機定位：`/sys/class/usbmisc/lp*/device` 真實路徑倒數第二段 = 設定的 USB bus-port（如 `1-3.1`）→ `/dev/usb/lpN`。
- 送印延遲：`(格口號-1)*400ms`（讓包裹先到格口）。
- 失敗重試：找不到裝置每 200ms 重試 30 次後發 `USB_DISCONNECT` 警報、3 秒後再試；寫入失敗同樣 30 次後發 `PRINTER_ERROR`、5 秒後再試；任務不丟。
- 現場已知：USB autosuspend 造成印表機掉線，需 `usbcore.autosuspend=-1`（`twfilter/USB檢查.txt`）。
